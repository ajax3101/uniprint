# Журнал архитектурных решений

Статусы: **предложено** — проектная гипотеза; **открыто** — нужен владелец/инфраструктурный факт; **принято** — подтверждено уполномоченными участниками. Пока ни одно техническое решение платформы не подтверждено университетом.

## ADR-001. Модульный монолит

- Статус: предложено.
- Решение: один backend с доменными модулями, отдельный web-клиент, PostgreSQL; фоновые интеграции изолированы адаптерами/коннектором.
- Причина: малая известная база исходного кода и необходимость общей атомарности движения запасов и заявок. Микросервисы не подтверждены масштабом или организационными границами.
- Последствия: модули разделяются в коде и транзакциях; распределённые сервисы не вводятся без измеримого основания.

## ADR-002. Кандидатный стек Python/FastAPI, PostgreSQL, React/TypeScript

- Статус: предложено, требует проверки инфраструктуры и совместимости.
- Причина: существующая заготовка Python и рекомендация ТЗ. В `pyproject.toml` установлен минимум Python 3.14, но веб-зависимостей нет.
- Последствия: до реализации проверить поддержку Python 3.14 всеми выбранными пакетами, способ сборки, доступность PostgreSQL и наличие фронтенд-инфраструктуры. Не трактовать рекомендацию как утверждённый стек.

## ADR-003. История движения картриджа неизменяемая

- Статус: предлагается как обязательный доменный инвариант.
- Решение: журнал событий/движений сохраняется; текущий статус — проекция. Исправления оформляются компенсирующей записью.
- Причина: материальная ответственность, предотвращение повторной выдачи, прослеживаемость заправок.

## ADR-004. Раздельные источники print telemetry

- Статус: предлагается.
- Решение: хранить device counters, IPP/job server records и ручные показания раздельно с происхождением и качеством; сверка является аналитическим результатом, а не корректировкой сырых данных.
- Причина: разные семантики и полнота источников; счетчик устройства включает потенциально неучтённые jobs, job records могут не подтверждать фактическую печать.

## ADR-005. Сбор печати сначала read-only и allowlist

- Статус: предлагается; сетевой владелец должен утвердить.
- Решение: сетевой коннектор опрашивает только явно заданные устройства/серверы, без автообнаружения; предпочтение SNMPv3/IPPS, только read-only.
- Причина: ограничение сетевого риска и соблюдение запрета на массовое сканирование.

## ADR-006. Согласование приложения не объявляется КЭП

- Статус: ограничение проекта до правового решения университета.
- Решение: фиксировать авторизованные внутренние решения; не утверждать юридическую силу без делопроизводственной/правовой оценки и, если нужно, интеграции с утверждённым ЭДО/КЭП.
- Основание: требование `CLAUDE.md`; применимость законов и внутренний порядок требуют профильной проверки.

## ADR-007. Fail-closed идентификация до подключения IdP

- Статус: временное решение разработки.
- Решение: по умолчанию API не принимает доменные запросы, пока нет провайдера идентификации. Локальный dev-адаптер доступен только в явном development режиме и только по loopback.
- Причина: не открывать каталог пользователей, заявки и складские операции без доверенной идентичности.
- Последствия: продуктовый вход и RBAC для университета ещё не реализованы; dev-заголовки нельзя включать на сетевом окружении.

## Решения, ожидающие заказчика

| Вопрос | Кто подтверждает | Блокирует |
|---|---|---|
| Размещение: локальный ЦОД/облако, сегментация, резервирование, RPO/RTO | ИТ/ИБ | Выбор эксплуатации и интеграционного коннектора |
| Источник учётных записей и организационной структуры | ИТ/кадры | Вход, роли и процессы пользователей |
| Юридический статус согласований/служебной записки, ЭДО/КЭП | Юристы/делопроизводство | Описание согласования как официального документа |
| Кто утверждает выдачу/возврат/списание и как подтверждается получение | Материально ответственные лица/руководство | Маршруты, роли и учётный журнал |
| Инвентаризация принтеров, моделей, подключений и серверов печати | ИТ университета | Пилот и реальные заявления о покрытии мониторинга |
| Допустимые персональные поля и аналитика индивидуальной печати | ИБ/юристы/кадры | Сбор идентифицируемых job records |
| Хранение журналов, заявок, вложений и экспорта | ИБ/делопроизводство | Схема хранения и политика удаления |
| Подрядчики, валюта, тарифы и документы на заправку | Финансы/закупки | Полный учёт затрат |
| MVP без автоматического мониторинга или с ограниченным пилотом | Владелец продукта | Приёмочные критерии и границы этапа |
